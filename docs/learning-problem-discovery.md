# Learning Problem Discovery — 找到值得研究的问题（V0.6.2 原版内完善）

## 发生了什么失效

在2026-10-10的 A股12只涨幅股 Learning 中，样本来自三个交易所的涨幅筛选规则。随后收集个股评论和行业研究，输出每家公司“行业需求能否转成利润”“利润为什么下滑”等正确但普遍适用的问题。

这些句子往往没有错，却没有回答：**为什么这些问题值得研究、它们能否区分看似相同的企业、结论是否会因不同机制而改变**。材料收集深入、数字正确、报告很长，仍不等于找到了关键研究问题。

**失败本质：系统把“已有用户任务/素材主题/表面问句”直接交给了 Problem Chain，缺少独立的 Problem Discovery。**

## 执行原则：不是尽可能深，而是选择能改变理解的主问题

在原先的 Ground 和 Problem Chain 之间按需使用：

> Ground（现实对象和原始任务） → Problem Discovery（异常/落差/竞争解释 → 候选问句 → 区分性证据 → 选择与修正） → Problem Chain（必要机制） → Reality Calibration（证据和边界）。

### 1. 不混淆四个层级

- **任务/问题域**：例如“从涨幅股样本学习公司与行业”。说明研究对象和目的，不自带上涨归因。
- **选样规则**：例如“北/沪/深各TOP3并纳入涨停同列”，这是取材方法，不是上涨原因。
- **主研究问题**：哪一种经营机制足以解释关键差异，什么证据能够区别它与竞争机制？可能是跨行业的，也可能是一个具体企业独有的。
- **机制子问题/证据问题**：例如“该公司是否有实际可持续付费客户、如何分账、经营现金流和资本占用如何变化”；这是研究主问题的路径，不能替代主问题本身。

### 2. 发现候选问题的证据入口

- **异常**：收入增长而利润下滑；模型声称完成文件读取但无 Tool Result；
- **对照**：同一行业技术进步，经营者A的利润下降、B的利润上升；
- **矛盾**：券商预计订单高速增长而财报仍然亏损；保底五年与实际租金现金流不一致；
- **被忽略的约束**：市场是否存在购买预算、谁拥有渠道或定价权、系统状态何时真正生效；
- **竞争解释**：同一结果可由需求、产品结构、成本、价格、资金、执行失败等不同机制产生。

候选问题是**需要研究的假说**，不能把偏好的解释包装成结论。

### 3. 问题优先级：少而有区分度

主问题至少应尽量满足以下性质（它们是思考约束，不是要求输出分数）：

1. **问题真实**：有可观察的落差、冲突、差异或真实待决策的难题；不是套用产业术语；
2. **解释增益**：能解释此前浅问题解释不了的事情，或明确区分两种以上因果机制；
3. **证据可追**：知道什么观察会支持或推翻某种解释；跨领域可以是源码、历史原始材料、合同、行为轨迹或数量；
4. **目标对齐**：回答后是否会改变用户的理解、下一步检索或行动；不把学习自动变成投资建议；
5. **边界正确**：避免选样偏差、过去和未来混淆、事实与研报观点混淆；当前材料不够时缩小结论，而不是寻找“大本质”代替证据。

### 4. 以此修复 A 股研究

**此前仅问**：中文在线短剧增长108.72%为什么仍然亏损？芒果超媒净利润为什么下降？

**初始张力**：AI内容制作成本可能下降、内容与IP收入增长，但内容公司仍可能亏损、会员付费却下降。它们的商业结构和业务阶段并不相同。

**候选机制**：制作成本、平台分账/获客、用户付费、内容留存、传统收入下滑、资本占用。谁驱动结果**尚未知**。

**更有区分力的研究问句**：在内容供给技术降本与短剧需求增长时，**企业凭借什么机制将新增需求保留为可持续利润？哪些企业把收益留住，哪些收益被渠道/成本/竞争消耗？** 

接下来分别核对中文在线与芒果超媒的**实际业务占比、分账、获客成本、会员付费和内容投入**；不能因双方都在传媒行业，就假定它们共享同一个答案。也不能基于单日涨幅证明市场恰好在定价这个机制。

换成对照组：东岳硅材的利润更多受产品—原料价差和产能/库存周期影响，不能强行套用“内容渠道”理论。跨公司的共同任务是**识别价值被谁创造、谁能保留、能持续多久**，但各公司必须保留自己的机制。

### 5. 跨领域验证

- **Agent**：从“模型太笨”转向“模型说完成任务与真实文件执行链之间缺哪条证据？”，先查结构化 Tool Call、文件版本和结果，再判断智能水平。
- **银行业务**：从“审批完成为何不能用信”转向“到底哪个状态与权限条件使一笔业务对用信端真正生效”；跟踪事件/责任，而不是直接宏大化为“银行数字化改革”。
- **健康**：从“枕头能否阻止打鼾”转向“出现症状时，需要排查的风险和足以支持因果的证据是什么”；不把没有数据的推测当确诊。
- **简单定义**：例如用户只问服务期限与付款承诺的区别，解释两个义务即可；不为了“深刻”不断延长问题链。

## 防止一种新失败：深刻表象

禁止：
- 把问题越写越宏大却无法提出一种新的证据或反例；
- 让问题预先包含结论（例如“平台必然攫取创作者所有利润，为什么？”）；
- 从只观察涨幅较大公司的样本，推断股票上涨的真实原因或超额收益规律；
- 用户明确问一个精确事实，却擅自变成行业根本矛盾或给买卖建议；
- 每个企业都生成统一四问表，等同于认为问题已经足够深入。

**停止条件**：已找到能区分关键机制且证据可获得的高价值问题，或发现现有材料无法区分竞争解释；前者继续机制研究，后者告知最小缺口。对低风险的清晰问题直接解答，不强制输出 problem framing 表。

## 验收

回归 #42–46 覆盖：
- 多公司材料与涨幅选样（避免选择偏误、过度归因）；
- AI内容降本但利益分配不确定（避免先定平台为原因）；
- Agent 文件处理失败（从现象跳到真假执行链）；
- 已知明确的银行状态问题（不泛化成长宏观命题）；
- 简单精确概念问答（不强行深挖）。

和此前 Reality Calibration 一样，静态脚本检验规范/fixtures/元数据，不代表模型在真实案例里已经找到真问题；需在同一模型/上下文下对照上一个 main baseline、比较研究问题的**解释力、区分证据、用户价值、长文副作用**。

D/R 的独立执行和完成屏障仍需要宿主 Trace；本规则只是 L 的质量约束，不改变执行职责。
