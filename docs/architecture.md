# 整体架构与职责边界

> **现行说明** · 对应仓库主入口 [SKILL.md](../SKILL.md) 及四条活跃 Skill。遇到任何冲突，以活跃 Skill 和实际宿主执行能力为准。

## 1. 为什么拆成四条 Skill？

一次知识任务经常混合四种不同目的：还原材料、判断材料、理解机制、继续发现问题。将它们写成一条“超级提示词”容易产生职责污染：摘要提前替作者做价值判断；审阅只看摘要漏掉原文；学习只拼接已有观点；练习为了完成流程而硬做工程项目。

SenseWright 将这些任务分开。**Skill 是认知工作方法，不是四个必然串行的程序阶段**。

| 维度 | D · Deep Read | R · Review | L · Learning | P · Practice |
| --- | --- | --- | --- | --- |
| 研究中心 | 原始材料 | 原始材料是否成立 | 用户想理解的现实问题 | 已有知识主干的未解问题 |
| 关键动作 | 恢复结构与推理后压缩 | 全面覆盖后独立判断 | 建立机制、查证、挑战并修正 | 检查遗漏、展开枝干、筛选并深入 |
| 典型产物 | 忠实认知重构 | 有重点的审阅判断 | 可解释、可迁移的知识模型 | 问题结构与重点枝干的深入解释 |
| 主要风险 | 漏关键推理、擅自批评 | 提前过滤、失去覆盖 | 证据没检验主问题、领域过拟合 | 随便挑一个细节、过度工程化 |
| 不承担 | 默认事实核查和反驳 | 依赖 D 的总结 | 未经授权的实际行动 | 默认工程实施、题库、用户能力评级 |

## 2. 两组容易混淆的区别

### D 与 R：忠实还原，不等于独立认同

D 回答“作者确实说了什么、怎样得出结论”，默认遵守原文边界。它可以明确“作者声称”或“材料假设”，但不主动用外部资料判定作者对错。

R 回答“哪些事实、推论、方案或行动依据站得住”，**从原始材料独立审阅**。它先为所有有语义内容的原文构建审阅单元，保留条件、例外、跨段依赖，再决定检查深度。**Materiality 决定最后报告什么，而不决定最初审什么。**

### L 与 P：建立理解，不等于继续发现枝干

L 可以在学习过程中校准问题和验证机制，过程是自适应的，并不是要强行打印 `Orient / Frame / Explain / Anchor / Challenge` 五个标题。特别要避免“例子算得正确，但只验证了旁支结论”这种问题—证据错位。

P 的目标不是再做一遍 L，而是沿已有理解检查**主干缺少了哪些必要前提、还有哪些能独立研究的枝干**。它先看问题空间，再深入关键分支，不强制分支数、对抗次数或工程交付物。

例如，L 已解释 “Model Request → Tool Call → Execution → Observation”，P 应当发现“为什么需要 Tool Call、模型怎样选择工具、参数如何落地”这些**上游主干缺口**，而不是只研究“工具执行超时”的下游异常。

## 3. 路由：先看目标，不按材料类型

| 用户目的 | 合适的路由 |
| --- | --- |
| “把这份材料读懂，保留完整业务事项” | D |
| “这份设计有没有重大遗漏？” | R |
| “既要忠实归纳也要独立审阅” | D + R，各自直接读取原文 |
| “我想理解这项技术为什么这样工作” | 本轮独立 D + R → L |
| “以前学过这个机制，进一步找到未解的关键问题” | P |
| “基于 Practice 发现的全新问题，正式重新学习” | 新一轮 D + R → L |
| “帮我完成普通格式转换或简单事实查询” | 不必强制套用 D/R/L/P |

如果同一个任务同时要求不同成果，先明确其独立目标，再决定是否组合。**L 的前置是强约束；P 不是 L 的自动后置步骤。**

## 4. Learning 的独立前置

```text
           同一轮 Raw Input
              /        \
       D 独立处理      R 独立处理
         不读取 R        不读取 D
              \        /
           二者全部完成
                |
                v
      L 读取 Raw Input + D + R
        选择性吸收，独立建模
```

执行要求：

1. D、R 均基于**本轮相同原始输入**；可以并行，但不能让 R 读取 D、或让 D 读取 R。
2. 两条前置都完成后 L 才开始。本轮历史缓存不能替代新一轮前置。
3. L 读取原始材料和两份结果，利用其结构、疑问与边界；D/R 的分析**不自动成为新的外部证据**。
4. 只有用户问题而没有独立材料时，D/R 也可以轻量执行，不能编造外部资料或超出原问题作长篇审稿。
5. **宿主运行时是实际隔离的责任主体**。Skill 文本能够声明约束，不能替宿主创建真正独立的模型上下文或证明已按顺序调用。声称“严格独立执行”需要可核查的运行记录。

P-only 可以使用既有知识模型；若发现根本知识缺口，可以提议新一轮 L，但提议本身不等于已执行 D/R/L。

## 5. 四条 Skill 各自的核心方法

**Deep Read V6.4**：恢复原材料真实认知拓扑 → 保留关键认知推进与必要解释 → 依用户目的选择 **Coverage-Preserving（独立认知单元完整覆盖）** 或 **Cognitive-Synthesis（核心认知模型不变）**。完整型不等于冗长；提炼型也不等于只剩结论。

**Vibe Review V0.10**：将原文拆成有意义的审阅单元 → 确认全文有语义内容均被覆盖 → 按单元性质选择合适审查方式 → 独立审阅 → 按重要性重点输出。重点报告不等于只审重点。

**System Learning V0.6.2**：理解用户的真实学习目的；按需调用领域基础理论；在证据、机制和反例之间往返；区分说明例子、机制演示与真正裁决主问题的证据；产生有边界的可迁移认识。历史 Domain Anchor、Problem Discovery、Reality Calibration 是历史设计线索，**不是三道永久新增的必经阶段**。

**Practice V0.3**：从已有主干检查遗漏 → 发现独立问题线 → 选择有辨别价值的方向 → 借真实案例、推演或查证深入 → 将新认识回流。这里是灵活的**认知责任**，不是固定五段结构。工程实践、方案对抗和面试追问只是不同应用。

## 6. 证据与执行的边界

区分至少四种情况：**原文/源码已查证**、**合理推演或教学假设**、**实际运行且有可复核记录**、**仍然未知**。

静态校验仅能说明文件格式、引用关系、字段合规；最小模拟只能支持其设定的情境；真实系统行为需用实际环境中的调用和观察证明。模型生成自己的示范答案，也不能替代对用户本人实践能力的测量。

这些边界是四条 Skill 的共同质量底线，但不会要求每一个简短任务都附上庞大的证据审计表。
