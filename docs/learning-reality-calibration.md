# Learning Reality Calibration — 通用现实校准设计（V0.6.2 细化）

## 问题从哪里来

Learner 能正确说出“行业需求增长 → 算力租赁有机会”，却无法判断一笔GPU租赁是否能回本；另一些问题（授信生效、程序执行、医疗主张）同样需要落到现实，却不能简单套用现金流模型。

目标不是在 Learning 后增加固定的“量化分析阶段”，而是**让机制理解足以辨别当前真实案例的成立条件与关键缺口**。

通用契约：

> 实际对象和原始证据 → 必要机制 → 最小区分性现实校准 → 调整结论或收缩边界 → 用通俗语言重建理解。

研究优先核对材料/可观察行为，教学优先从问题与机制讲起；不是让精密数字替代真实证据。

## 一、何时触发

仅在以下任一条件影响结论时触发，不因材料属于“财务/科技/银行/医学”而自动触发：

- 数量级、容量、价格、频率、成本、时序和阈值决定结论；
- 某个具体执行状态、控制流或角色交接决定结果；
- 观察样本、比较口径、数据来源和证据等级可能推翻原判断；
- 一个现实反例或单条件变化可以显著缩小结论的适用边界。

简单定义、清晰的低风险概念解释如果已通过一个小例子澄清，就停止，不为“看起来严谨”强制补数字。

## 二、从对象选择证据，而不是从领域套模板

| 对象 / 问题 | 最小现实锚点 | 不该强行做的事情 |
|---|---|---|
| GPU租赁能否回本 | 采购价、可计费小时、合同最低付款与客户信用；条件敏感性 | 在合同未披露时推算“公司确定盈利” |
| API p95为什么高 | 一条关键路径+代表性请求分布；必要时只变化一个耗时 | 单个Trace代替总体p95；分阶段p95强行相加 |
| 授信审批后为何不能用信 | APPROVED→SIGNED→EFFECTIVE，一笔生效条件未满足的单据 | 无业务记录却编造审批完成率/银行制度 |
| 医学经验能否推广 | 个体体验 vs 可靠临床证据、适用人群、反例和安全边界 | 用两条评论推导治愈率或替代医疗诊断 |
| DDR4在售报价对比 | SKU、容量/频率、交易类型、时间点与价格来源 | 把不同频率的成交价/挂牌价称作同品类市场涨幅 |
| 简单五年服务期概念 | 服务期限 vs 最低付款责任的小例子 | 无意义的公式、财务模型、表格或实验 |

上述数值或案例若来自合成 fixtures，只能作为教学推演，不是项目核验与实测事实。

## 三、最低可用的 Reality Calibration

1. **先定位机制如何影响现实结果。** 问“为什么这个判断成立？依赖什么前提？什么现象会反驳它？”
2. **选择一个最有区分度的锚点。** 优先已有的合同条款、单笔状态记录、执行trace、可比较的价格、公开研究；缺少证据时说清未知而非编造。
3. **只做必要的变化。** 如使用率70%→50%；如果固定最低付款，改变使用率不必然改变应收租金；解释哪一个条件先改变结论。非数量型问题直接改变状态/流程/样本前提。
4. **分离证据类型。** 原始观察 / 外部核验 / 教学假设 / 推导 / 未知，不能混写。口径不同时停止外推，不能因为算术正确就认定比较真实。
5. **简明回归生活语言。** 告诉读者“原先怎么看、现在哪个条件改变了判断、需要去哪种真实证据核验”；不需要每次打印分类表。
6. **停止条件。** 当校准不能进一步改变理解或结论已经被关键缺证卡住，就停止计算。若用户要求真实建模、实施、执行与交付，再明确路由 Practice；不能自动把任何 Learning 变成长财务报告。

## 四、注意与已有机制的边界

- **D/R → L 不变。** D 和 R 从同一份 Raw Input 独立执行，L 使用它们作为脚手架；现实校准属于 L，不能把 R 的审阅意见伪装为事实。
- **与 Mechanism-to-Implementation Mapping 配合。** 源码看调用链、业务看状态流转、实验看可重复观测。现实校准只问“这些机制在当前真实条件下成立吗”，不会强迫补代码。
- **与 Contrast & Vary 配合。** 尽量单变量变化，但如果现实中同时变化的因素会使因果判别无效，就明确边界而非宣称某一个变量是唯一原因。
- **与 Practice 区分。** 理解为什么选某种测试仍是 Learning；实际编写、运行、调优、验证及交付完整工程属于 Practice。

## 五、验收策略

新增 eval #36–41：
- **数量敏感**：GPU设备租赁假设，不把订单需求增长当盈利证据，也不无谓生成DCF。
- **工程观测**：API性能 trace，不能用一个样例代表总体p95。
- **非数量业务流程**：银行审批/签约/生效状态核验。
- **专业证据**：医疗叙述不从社交评论推导临床结论。
- **可比性**：内存不同SKU、不同交易口径，不因准确除法就宣称总体涨幅。
- **Skip回归**：简单服务期概念不强迫任何数据或模型。

针对 `learning_v0_6_2_pre_reality_calibration` baseline，需相同模型、采样参数、输入与相近执行时间运行 A/B，人工检查是否**更容易理解真实条件**，而不仅是更长、更专业、公式更多。静态脚本仅检查结构与元数据，不能证明行为或D/R运行时隔离。

该文档用于解释具体取舍；核心路由契约以 `skills/system-learning-v0.6.2/SKILL.md` 为准。
