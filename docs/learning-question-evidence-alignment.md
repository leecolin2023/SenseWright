# Learning 案例与主问题的检验对齐（2026-10-11）

> **历史案例复盘（非独立现行门禁）**：本文解释 Learning 为什么必须区分“说明例子”和“检验主问题的证据”。这一原则已吸收进入当前 [Learning V0.6.2](../skills/system-learning-v0.6.2/SKILL.md)，不应从本文再独立新增强制 Case Gate。

## 发现的真实失误

一次关于“个人投资中，较高确定性是否足以支持集中持有与杠杆”的 Learning，找到了有价值的主问题，却用“股价下跌30%，2倍杠杆时权益下跌60%”作为主要检验。这个计算没有错，但它回答的是**杠杆放大盈亏**，并不回答**主观确定性在什么条件下足以支持杠杆决策**。随后即便增加更多精确的小数，也无法弥补所检验命题错位。

这是一般性失败：**例子真实、数学正确或动作完成，不等于它与原研究问题之间存在逻辑上的判别关系。**

## 抽取的通用修正

本轮**不新增认知阶段、固定输出模板或财务公式**；只在现有 Anchor / Challenge / 质量门禁中补齐证据用途与检验目标之间的联系。

### 例子可能承担不同职责

- **Illustrate（帮助直观理解）**：让新读者理解定义、感受一个现象。一个简单例子就够，不能因此声称证明普遍结论。
- **Trace（展示实际机制）**：让关键输入、状态、动作、结果的具体链路可见。它可以证明某一给定例子如何工作，但不必然说明为何选这个机制、在别的条件下是否生效。
- **Discriminate（检验/区分关键判断）**：明确核心命题与竞争解释，寻找在它们之下应出现**不同观察结果**的条件、案例或反例。无法区分就收缩主张/标为未验证，而不是继续堆数据。

没有必要每次答题都提供第三种。用户仅要求解释短概念时，Illustrate 或 Trace 已经够用。对于试图评价争议性因果、设计取舍或重要投资命题的 Learning，才需要主动检验是否具备判别性。

### 内部的三问（思考用途，不是最终输出模板）

1. **主问题是什么？** 例如“高经营确定性是否足以支持加杠杆”。
2. **当前例子实际能支持到哪句话？** 例如“2倍敞口将线性涨跌放大”；不能偷换成“高确定性应该加杠杆”。
3. **两种相关判断在这个案例里会得到不同结果吗？** 如果不会，哪一个最小的变化（价格、资金约束、时间路径、干预、错误路径、复核来源）会让结果分歧？如果现有材料不足，能精确说明缺什么即可。

这三问应在内部用于修正**例子的选择和解释力度**，不要再建一个独立“Case Gate”或要求所有用户阅读前置检查清单。

## 跨领域回归的失败模式

| 主问题 | 看似相关但没有判别力的例子 | 能区分关键机制的最低补充 |
|---|---|---|
| 高主观把握是否足以支持加杠杆？ | 2倍杠杆亏损变2倍 | 同公司不同买价、同终点不同回撤路径/融资约束等，可反转或限定策略结论 |
| Agent如何决定调用哪个工具？ | 已选中的工具执行成功并返回 Observation | 对比本地文件、知识库检索、复合意图等不同请求，检查可见工具描述和结构化选择事件 |
| 合同未生效时能否阻断用信？ | 正常单据签约、生效后成功用信 | 一笔已审批但缺生效条件的负样本：正确门禁与缺陷门禁出现不同结果 |
| 咖啡与睡眠是否有因果关系？ | 晚间喝咖啡的人睡得少1小时 | 控制考试压力、作息等混杂的比较设计；未有新证据时不得断言已证因果 |
| 同步和异步的区别？ | 两句话与一个直观例子 | **无需额外实验**；只需定义准确和范围清楚 |

这些都是**测试语料**，不是应当写进 Runtime Skill 的行业规则。

## 验收及边界

- 新增 Eval #59–63，保留 #1–58；冻结变更前的 main commit 作为基线。
- 核心正向断言：模型可说清“实际检验的命题 ≠ 应回答的命题”，能选择让竞争解释产生差异的最小证据/条件，并区分示例推演与实际核验。
- 反向断言：**不强迫**短概念说明做实验；不在每个议题都制造二选一的竞争假说；不把教学情景伪装成实测；不凭模型内部的推演宣称问题在真实世界已被证实。
- 主观评价的“问题是否有意义、例子是否有解释增益”必须通过实际模型输出 A/B 或人类审阅判断。GitHub CI 只能核验测试元数据/文件存在，**不能证明真实行为已改善**。
- 不改变 D/R→L 前置职责、Runtime 隔离要求，也不把详细金融概率计算引入通用 Skill。

**判断原则：用例的复杂程度不是质量指标；它能否支持或区分正在讨论的那个判断，才是。**
