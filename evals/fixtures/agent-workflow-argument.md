# 合成材料：为什么 Agent 工作流不应全部写死

一个团队正在开发内部研究助手。第一版把所有任务都写成固定流程：检索、总结、比较、写报告。这样做的优点是可预测，缺点是不同任务仍会机械执行全部步骤。

团队后来提出：稳定、可验证且每次都需要的步骤继续写成 Workflow；只有当下一步取决于上下文、需要在多种动作之间选择时，才交给 Agent 判断。作者据此提出一个判断：Agent 不是 Workflow 的替代品，而是用来处理流程中无法预先完全枚举的决策点。

作者举了一个例子。用户只要求“概括这份公告”，如果系统仍然执行外部检索和多源比较，不仅浪费 token，还可能把外部信息混入忠实摘要。相反，如果用户要求“判断公告中的说法是否可靠”，外部核实就可能成为必要动作。

作者最后强调，这不是说固定流程永远更好。真实系统通常同时包含确定性步骤和 Agent 决策，关键是把不确定性放在正确的位置。
