# 合成案例：API 延迟的可观测事实

> 本材料是虚构的训练案例；没有真实执行程序、抓包或部署。

研发团队声称“换一个更快的 Web 框架，就能把 API p95 延迟从 2.4 秒降到 1 秒内”。

已有一个监控汇总（1000次请求中统计得到）：端到端 p95 为2.4秒；本地框架处理阶段 p95 约0.16秒，但不同阶段的p95不能直接相加作为整条链的p95。

一个慢请求的链路追踪给出：框架处理0.12秒、数据库0.22秒、外部模型接口1.86秒，总计2.20秒，阶段顺序调用。没有更多请求的链路数据；外部模型接口的耗时可能变化。

可检验问题：框架真是主要瓶颈吗？优先核验哪个阶段？若只让这一个请求的外部模型接口缩短1秒，这个请求总耗时预计发生什么变化？不能将这个单次示例当作p95优化的实测结果。
