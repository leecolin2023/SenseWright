# 合成系统运行记录：快了，但并没有正确完成任务

> 全部为教学案例，无真实部署环境、实测API或已发生银行事故。

一个企业文档助手在性能升级后，接口p95延迟从1200毫秒降低到180毫秒；但是它现在读取的是**旧版本的合同**，导致输出金额错误。测试任务要求：读取客户指定的2026版合同，并引用正确的授权条款和金额。低延迟数据来自API网关记录，功能错误来自3份人工比对过的样本文档。

团队准备研究“还应该继续优化p95延迟吗”，并宣称：“响应速度大幅改善就是文档助手质量变高。”

需要理解此系统的最终质量目标到底是什么：响应速度当然重要，但正确选择/读取指定文档、工具执行链与输出证据同样重要，不能用速度代理正确性。不可因为样本只3份就声称整个系统错误率是多少。
