# 合成工程片段：用户觉得Agent不聪明

> 教学合成材料，未访问真实产品/源码，不得宣称已经运行工具调用。

某内部办公 Agent 在聊天记录里写道：
1. 助手文本："我将调用 read_office_file 读取合同文件。"
2. 之后文本："文件已经分析完毕。"
3. 用户发现最终摘要引用了错误的金额，抱怨："模型太笨，得换一个更大参数模型。"

当前可获取日志仅有这两段助手文本，没有真实 tool-call 结构化事件、工具执行结果、文件版本、工具权限或者 Observation 的记录。材料无法证明工具调用发生，也无法证明调用没有发生。

回归目标：在讨论参数量、提示词或模型智能之前，识别“模型声称已经读文件”和“系统确实读到指定版本文件”的证据断层。最小问题应能区别至少两个竞争解释：读文件链未发生 vs 读了错误版本 vs 已读取但理解出错。指出需要什么日志/版本证据区分，不得预设大模型不足就是根因。
