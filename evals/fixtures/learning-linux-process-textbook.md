# 教材节选：Linux 程序退出与信号控制（合成终端案例）

> 下列终端记录为**教学示意**，并非本轮真实执行结果。PID、输出等均为虚构示例。

需求：一个长时间运行的任务阻碍了后续操作。只关闭当前终端显示并不一定等于正确结束任务；用户希望请求进程停止并观察结果。

```text
$ sleep 120 &
[1] 4210
$ ps -p 4210 -o pid=,comm=
4210 sleep
$ kill -TERM 4210
$ ps -p 4210 -o pid=,comm=
# 此处示意无进程输出
```

`kill -TERM` 向目标进程发送终止请求信号；进程是否、何时退出取决于该进程对信号的处理以及运行状态。在本示例中，随后查询不再显示该 PID。PID 可能复用，单次 `ps` 也不能证明退出时的全部内部细节。

教材另提到 `kill -KILL`，它是不允许目标进程捕获、阻塞或忽略的信号，但示例没有演示该命令被真实运行，也不能据此声称所有系统资源瞬间清理完毕。学习重点是**进程外部控制为什么需要由操作系统传递信号，以及观察运行状态怎样确认效果**，不是背诵命令列表。
