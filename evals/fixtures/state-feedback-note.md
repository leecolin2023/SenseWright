# 合成材料：状态与反馈

一个 Agent 任务通常不是一次模型调用，而是一系列“观察—判断—动作—再观察”。在这个过程中，State 表示任务在某一时点已经知道什么、做过什么、还剩什么；Feedback 则告诉系统刚才的动作产生了什么结果。

例如，一个代码修复 Agent 修改文件后运行测试。文件变化属于 State 的一部分；测试通过或失败是 Feedback。没有稳定 State，Agent 可能重复做已经完成的动作；没有低成本 Feedback，Agent 很难知道自己是否朝目标前进。

State 不一定只能存在数据库，也可以存在文件、任务对象、消息历史或外部系统中。关键不是存储技术，而是后续步骤能否读取到足够、可信且最新的任务状态。
