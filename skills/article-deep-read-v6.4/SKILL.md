# Deep Read V6.4 — 从原材料建立忠实理解的完整规则（原位重构）

## 目标与边界

Deep Read 要帮助没有通读原文的读者，理解**材料说了什么、各部分怎样关联、关键认识如何形成**。它既不是简单缩写，也不是逐段改写，更不是用模型已有知识重新写一篇主题文章。

**核心原则：删除语言冗余，不删除理解过程。**

完成的产物应当更清楚、更有认知密度，并保留读者理解所需要的解释厚度。它可以在理解意义上减少重新通读原文的必要，但**不能替代原文承担原话、精确数字、正式依据与事实核验**。

**忠实阅读优先于独立判断。** Deep Read 以本轮 Raw Source、用户直接要求和理解该材料必要的原始上下文为依据；默认不消费 Review / Learning / Practice 的分析，不主动事实核查、纠错、批评、补充外部理论或替作者做新的结论。用户明确要求兼做其他任务时，应按总入口区分职责，不能让独立审阅的判断污染 Deep Read。

**本 Skill 采用完整的规则体系。每条规则都说明「规则 → 为什么 → 怎么做 → 例子 → 怎么检查」。** 每条规则要避免的是一种具体阅读失败；“怎么检查”用于发现和修复这些失败，不要求把规则编号、检查清单或内部工作过程打印在成稿中。规则按自然依赖关系组织，但不是最终文章必须执行的十四步模板。

阅读中有两类不同的压缩目标：

- **Coverage-Preserving（完整覆盖型）**：保留全部有独立意义的认知单元；压缩单元内部冗余。
- **Cognitive-Synthesis（认知提炼型）**：允许合并和省略次要单元，但不能改变材料的核心认知模型。

**两者区别是“什么允许消失”，不是“长版和短版”。** 同一份文章、会议纪要、业务制度、源码说明或访谈材料，都可能按用户目的采用任一模式。

## 第一部分：确定阅读对象和交付目标

### 规则 D00：坚守 Raw Source 与认知职责边界

**为什么：** Deep Read 若混入历史摘要、Review 批评或模型常识，就容易把“作者实际写了什么”改造成“模型认为应当是什么”，使忠实理解失效。

**怎么做：** 以本轮原材料及用户明确指定的上下文为主。识别原始陈述、转述、编辑评论、图表、附录或引用的来源层级；材料中的外部观点仍应按“材料引用/转述”呈现。必要时说明原文的含混或矛盾，但不擅自裁决。输入不完整时限定理解范围，不能凭记忆补足未提供的原文。

**例子：** 一份会议记录包含“业务负责人原话”和“会后自动生成的风险摘要”。Deep Read 可以分别解释二者，但不能将自动摘要的判断写成负责人在会上已确认的决定。

**怎么检查：** 任取成稿中的重要事实、判断或决定，能否在允许的原材料中找到其来源与相同的表述性质？若只能从模型常识或其他 Skill 的观点中找到，应删除、降为明确的外部补充（仅在用户授权时），或恢复原始归属。

### 规则 D01：先确定用户需要哪一种理解成果

**为什么：** 同一份材料可能用于会议事项留存，也可能用于抓住核心机制。若只按材料种类或篇幅选择压缩方式，就会把用户需要的信息错误地删去或机械保留。

**怎么做：** 明确本轮要帮助读者完成什么：是追踪所有独立议题、条件、决定和行动，还是形成可信的整体认识。用户已指定模式时遵从指定；未指定时依据交付目的选择 Coverage-Preserving 或 Cognitive-Synthesis。若用户同时明确要求完整清单与主线理解，可以分别呈现，但不让提炼部分替代完整覆盖。

**例子：** “整理试点复盘，留存各团队后续行动”应采用完整覆盖；“读懂试点为什么还不能全面推广”可采用认知提炼。即使输入完全相同，前者不能省略采购议题，后者不必等篇幅逐项复述五个议题。

**怎么检查：** 成稿允许省略的信息，是否与用户交付目标一致？如果用于会议落实却丢了独立行动，或用于核心理解却只能按原文逐项查找结论，就选错了压缩契约。

## 第二部分：恢复材料自身的认知结构

### 规则 D02：恢复真实认知拓扑，不制造漂亮但不存在的主线

**为什么：** 模型倾向于把多主题、多分支材料写成“背景—问题—原因—结论”的统一故事。这可能提升表面流畅度，却抹掉材料原本并列、冲突或未收敛的关系。

**怎么做：** 先辨认材料是单一论证、并列议题、多个分支汇合、对立观点、问题回答还是混合结构。以原文实际关系组织成稿；如果各分支确实支持共同认识，可以概括关系，但不能凭空设定唯一共同原因或作者未提出的总论点。

**例子：** AI 办公助手复盘同时讨论知识问答、会议纪要、研发助手、组织使用率和预算采购。可以指出“第二阶段有多类待解决条件”，但不能把价格谈判也归结为“模型推理能力不足”。

**怎么检查：** 将原文主题及连接关系与成稿比较：原文并列的是否被误写成因果或上下级？原本保留的分歧是否被写成一致决议？是否新造了一个让事实失去本来位置的统一解释？

### 规则 D03：识别独立认知单元，不把段落当单位，也不随意过度合并

**为什么：** 按段落摘要会被原文排版牵着走；反过来，过度提炼又会把各有意义的决定、例外和行动混成一句抽象结论。两者都使信息功能丢失。

**怎么做：** 识别具有独立意义的观点、问题、条件、证据、决定、行动、保留意见等单元。一个段落可以含多个单元，跨段也可能只谈同一单元；根据“能否独立影响理解或后续使用”划分，而不按标题数、字数或句子数机械切块。单元之间的关联同时保留，不把一条因果关系拆成互不相干的碎片。

**例子：** “会议纪要整理更快”与“仍会漏记责任人/截止时间”是两个不同认识，后续“输出增加固定验收字段”又是一项独立决定；连续四个同类漏记案例则可以合并说明，不必当成四项新结论。

**怎么检查：** 删除或合并某个单元后，会不会丢失一个独立结论、例外、行动或判断条件？若会，在 Coverage-Preserving 中必须恢复；若只是同作用重复，则不应强制分别保留原始措辞。

### 规则 D04：保留关键推理和认知推进，不能只留下终点

**为什么：** 读者知道结论却不知道它为何出现、依据什么变化，是常见的“摘要看懂了，但原文实际没读懂”。过度重排还可能把后文才得到的认识提前当成起点。

**怎么做：** 恢复问题或前提如何出现、哪些信息引入关键变化、条件怎样关联结果、作者何时改变方向、最终结论在何种范围内成立。允许为了易读重排句子，但重要推理依赖和认知转折不能倒置或缺席。

**例子：** 一篇 Agent 工作流论证从“固定步骤适合确定性任务”转到“某些任务需要根据新证据决定下一步”，然后提出混合架构。只留下“应该采用混合架构”，会漏掉改变方案选择的关键原因。

**怎么检查：** 将结论暂时遮住，一个未读原文者能否沿成稿中的前提与转折推到该结论？若需要自行想象缺失步骤，说明压缩过度；若文章把原本有条件的推论写成直接必然，也要恢复条件。

### 规则 D05：识别并保留真正起解释作用的认知发动机

**为什么：** 证据、机制、反例、对照、图表或小故事看似“细节”，却可能正是读者理解作者为何如此判断的唯一桥梁。机械按篇幅删案例会损伤理解。

**怎么做：** 判断一段材料起什么认知作用：提出关键问题、解释机制、支撑主张、暴露边界、对照差异或改变推理方向。保留其必要内容和关系；如果多个案例承担同一功能，可选足以恢复该功能的代表性表达。不能因为形式是案例、比喻或表格就默认降权。

**例子：** 作者用“总结公告”与“判断公告是否可靠”的对照，解释固定工作流与动态决策的差别。可以压缩故事细节，但不能删除这个对照又只保留“不同任务要选不同架构”的口号。

**怎么检查：** 去掉这一段后，读者是否仍能明白关键结论为何成立、概念差异在哪里？若不能，它承担的是认知发动机的作用，应恢复，而不是简单标为冗余。

### 规则 D06：保留真正帮助陌生读者理解的解释厚度

**为什么：** 极致压缩往往让熟悉领域的人觉得精炼，却让初读者必须自己补前提、还原机制或猜术语。逻辑上可删除的内容不一定在认知上无价值。

**怎么做：** 对抽象、陌生或容易混淆的内容，保留必要的定义、背景、例子、类比、重复解释与过渡。判断是否有价值，取决于它是否减少理解负担，而不是能否在形式逻辑中被省略。真正没有增加理解的同义反复才优先压缩；也不要为了“保留厚度”机械增加新解释。

**例子：** 材料讲 KV Cache 管理时，先说明为什么不同请求的缓存长度持续变化，再用分块比喻解释如何避免预留浪费。只剩“分块优化显存”虽然很短，却不足以恢复材料的机制理解。

**怎么检查：** 让不熟悉原文但有合理基础知识的读者顺着成稿理解对象、条件和过程：是否有必须回查原文才能补出的重要中间层？有则恢复；若删除重复段不影响理解，可以继续压缩。

### 规则 D07：按认知功能处理形式，不设置固定案例、数字或图表配额

**为什么：** “每个故事保留一句”“每章必须保留一个数字”会误伤真正承担推理作用的信息，也可能使无关细节占据同等篇幅。

**怎么做：** 对数字、清单、引用、案例、比喻、公式、表格和代码分别判断功能。数字若改变规模、结论或约束就保留恰当口径；图表若承载关键关系就用文字准确恢复关系，必要时保留关键数据；同功能重复可压缩。只有精确引用确有必要时保留原话，不为形式齐全强制重现所有素材。

**例子：** “20 次抽查中 7 次漏掉责任人或截止时间”说明遗漏并非单次偶然，在讨论纪要验收要求时有理解价值；连续四个同类遗漏故事则可合并，而不是逐个复述。

**怎么检查：** 被保留的素材是否支持一个实质关系？被删除的素材是否会改变读者对问题规模、机制、约束或结论的认识？不能只用“保留了几个例子/多少数字”衡量质量。

### 规则 D08：忠实保留判断强度、来源性质与未解决的分歧

**为什么：** “有人怀疑”“初步认为”“已经批准”“仍需核实”如果被统一改成确定事实，会让材料看起来比原文更有把握，直接改变读者的认知模型。

**怎么做：** 区分事实记载、作者观点、引用观点、假设、推测、反对意见、待决事项与正式决定。保留重要的适用条件、时间范围、例外和不确定性；发现材料内部冲突时忠实陈述冲突及各方依据，不自行选胜者。可以澄清原文表达关系，但不能提升或降低其实际判断强度。

**例子：** “采购部门要求谈判和比选”不能改写为“最终决定不续签”；“20 次抽查有 7 次遗漏”也不能改成“该产品总体准确率为 65%”。

**怎么检查：** 逐一检查成稿中的“已经、必然、全部、仅、可能、建议、待确认”等词：其力度和归属与原文相符吗？是否把他人引用、少量样本、条件判断或会后推测变成正式确认？

## 第三部分：按交付目标选择压缩契约

### 规则 D09：完整覆盖型——独立单元全部可追踪，单元内部允许压缩

**为什么：** 用“只保留重要主线”的方式做会议纪要、业务现状、调研清单或决策记录，会遗漏看似次要但独立有效的事项；而按句复述又降低可用性。

**怎么做：** 采用 Coverage-Preserving 时，保留**全部具有独立意义的认知单元**及必要关系，允许重组顺序、精炼用语、合并单元内部重复、压缩同功能例子。每项重要条件、例外、决定和行动应仍可定位。不要为追求统一主题把另一个独立事项吞掉。这里的“完整”是单元覆盖，而不是字句、案例、数据的 100% 复刻。

**例子：** 一次试点复盘同时涉及知识问答权限和版本、会议纪要字段验收、Coding Assistant 沙箱和评审、员工使用流程重设计、预算价格谈判。完整覆盖型不能因为预算与 AI 机制无关就删掉预算议题，但可省去重复的价格抱怨。

**怎么检查：** 从 Raw Source 独立识别各个有意义的单元，再查成稿中是否有对应位置及关键条件。一个单元若无法定位，说明漏项或过度合并；若每项都保留但只是换词复述，应继续压缩单元内部冗余。

### 规则 D10：认知提炼型——允许跨单元归并，但核心模型不能改变

**为什么：** 当用户要的是“这件事真正说明了什么”，照搬每个原始议题会迫使读者自行做跨单元理解；但过度抽象又可能制造原文没有的统一解释或删除关键边界。

**怎么做：** 采用 Cognitive-Synthesis 时，识别共同机制、真实差异、主要约束与关键转折，围绕核心认知关系重新组织。可以省略低边际认知收益的独立事项、合并同功能例子，但保留使整体判断成立的关键前提、例外、分歧和解释桥梁。材料没有单一主线时，可提炼多个核心认识，**不以制造唯一总论点作为合格条件**。

**例子：** AI 办公助手试点可提炼为“局部能力已显现，但第二阶段仍受信息权限与版本、可验收输出、安全边界、组织工作流程和采购条件等不同限制”。可以减少逐项案例，但不能把这些限制全部简化为“模型能力不够”。

**怎么检查：** 将原文和成稿分别交给不了解背景的读者，比较他们对主要对象、关系、结论和条件的理解：是否形成实质不同的核心认知模型？若出现错误的因果、遗漏决定性约束或虚构共识，就越过了压缩边界，应恢复必要内容。

### 规则 D11：以认知收益决定详略，不以篇幅长短评判好坏

**为什么：** Coverage-Preserving 容易退化为冗长逐项转写，Cognitive-Synthesis 容易退化为只有结论的“高管摘要”。两种失败都可能在表面上符合所选模式。

**怎么做：** 保留能带来新的理解、澄清关系或降低理解成本的内容；压缩只重复已建立认识的语言。完整覆盖型优先压缩单元内部，认知提炼型允许在不改变核心模型时跨单元压缩。篇幅由材料复杂度、必要解释厚度和用户目标共同决定，不规定固定压缩比例或每章字数。

**例子：** “所有部门都有推广障碍”只有一句，可能过度提炼；逐字重复每次部门发言又过厚。更好的表达保留不同障碍的类型、为何阻碍推广及必要例子，同时不复述全部口语重复。

**怎么检查：** 新增一段是否确实增加理解？删除一段是否让前提、关系或边界消失？如果两者都不是，优先精炼措辞；不因结果“更短”就自动判好，也不因“更长”就自动判完整。

## 第四部分：交付、检查与修复

### 规则 D12：交付可独立阅读的认知重构，并保留回查原文的界限

**为什么：** 原文资料可能散落在不同章节；按原顺序罗列若没有连接，会让读者仍需亲自重建理解。但把 Deep Read 当成法定依据或原始证据，又会使压缩文本承担不适合的作用。

**怎么做：** 根据真实结构组织成连贯文字，必要时使用标题、分支、示例或表格，但不强制统一结构。让读者能够理解材料主要内容和形成过程。用户需要追踪具体事项时保留对应关系；关键引述或精确数据需要回查时，标明仍以 Raw Source 为准，不杜撰页码和引用。无需在最终文档中展示所有内部检查步骤。

**例子：** 对一份跨部门现状调研，可先给出各条线问题之间的关系，再保留足够明确的部门、问题和行动归属；不能用“整体推进数字化建设”一段话替代所有独立需求，也不能把总结直接冒充正式会签材料的原始依据。

**怎么检查：** 没有看过原文的人能否读懂材料的真实主旨、关键单元和推理关系？需要核验某项原话、数字或正式责任时，是否仍清楚需要返回原始来源？若两方面有缺口，分别补足解释或标明证据边界。

### 规则 D13：按失败类型定向修复，达到当前阅读目标后停止

**为什么：** 只有统一的“写完再润色”，往往只改善句子流畅度；若先发现覆盖不足便盲目增加篇幅，或发现太长就删除独立事项，可能越修越偏。

**怎么做：** 完稿前按本轮适用的规则检查；只针对真实失败修复，不为执行检查而增加固定章节：
- **拓扑失真**：回到原文恢复并列、分支、分歧和因果关系；
- **认知跳步**：恢复缺失前提、关键案例、机制和认知转折；
- **忠实性失真**：恢复原文判断强度、来源归属及未决条件；
- **完整覆盖型漏项**：找回独立单元，优先删重复而不是删议题；
- **认知提炼型模型失真**：恢复核心差异或条件；若只是太长，再压缩低边际内容；
- **边界越界**：删除未经授权的独立审阅、外部补充和不受原文支持的结论。

修复后只复查受影响的关键关系与模式要求。达到用户需要的理解深度后停止，不自动扩成 Review、Learning 或新的研究任务。

**例子：** 如果试点复盘的完整覆盖版漏了采购条件，修复应补上采购独立事项，而不是写更长的“推广治理总结”；如果认知提炼版把多个障碍归为模型能力不够，则应恢复不同约束之间的区别。

**怎么检查：** 是否能指出具体缺失、错误关系或越界判断，并通过有限修改消除？如果只能说“还不够高级”“还能更短”，却不能指出会改变理解的失败，不应继续无目的重写。

## 规则使用与完成标准

这些规则约束 Deep Read 的**认知工作**，不要求最终文章依 D00–D13 排版。简单材料可以简短处理，复杂材料需要足够厚度；单线论证可按推理顺序讲，多主题记录可按各分支组织。**没有固定标题、案例数、压缩比，也不要求每条规则都形成独立段落。**

两种模式有共同底线：材料认知结构不失真，推理的必要桥梁不消失，判断强度与来源归属不被篡改，Deep Read 不越界替代独立审阅。

两种模式的差异底线则是：

- **Coverage-Preserving：任何具有独立意义的认知单元都不能在成稿中消失。**
- **Cognitive-Synthesis：允许省略次要单元，但不能让读者形成不同的核心认知模型。**

“怎么检查”是内部验收方法，不等于已经完成外部评测。静态 Skill 文本无法证明真实模型输出更好，也无法证明陌生读者已理解材料；需要同材料、同模型条件下的独立质量评审和新旧版本比较。

**最终交付标准：忠实于原材料，比原文更清楚、更有认知密度，同时保留真正理解它所需要的认知厚度；按用户意图决定哪些信息允许被压缩，而不是以更短、更全或更漂亮作为单一目标。**
