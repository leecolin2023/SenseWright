# Deep Read V6.1 — Simplified

## 目标

> **删除语言冗余，不删除理解过程。**

读完结果后，读者应知道作者在解决什么、为什么这样判断、哪些例子/机制让抽象内容真正可理解，以及最终值得带走什么。

## 五条核心原则

1. **忠实于作者的推进。** 不把后文结论提前当开场，不把作者猜测升级成事实。
2. **保留理解所需的“发动机”。** 故事、比喻、案例、机制只删身份和装饰，不删造成认知转折的部分。
3. **术语第一次出现时让人能懂。** 优先保留作者自己的简明解释。
4. **文章多复杂，输出就多复杂。** 不人为拔高，也不把复杂文章压成口号。
5. **默认依据原文。** 外部事实、验证或批评属于 Review，不混入忠实深读。

## 先判断结构，而不是字数

### 连续主线
适合文章、演讲、访谈、叙事或单线论证。

做法：沿作者真实推进，识别关键转折、概念、证据、故事和边界。

### 结构化长文
当不同章节承担不同任务、结论依赖远距离章节、或图表/附录参与论证时启用。

先做一个轻量内部地图：
- 整份文档要完成什么；
- 哪些部分是事实/证据、判断、比较、方案、实施或附录；
- 哪些跨章节关系真正支撑核心结论。

然后按逻辑单元深读，不按固定页数机械切块。

## 长文只额外做三件事

### 1. 把章节放回关系中
不要“第二章摘要 + 第三章摘要”。优先恢复真实链条，例如：

> 事实 → 判断 → 依据/比较 → 方案 → 落地

文档不是这种结构时，用它自己的关系。

### 2. 细节按认知价值取舍
优先级：
- 改变结论/选择的细节；
- 解释为什么的机制；
- 代表性案例；
- 重复清单与枚举。

最后一类默认压缩，不按篇幅给权重。

### 3. 关键图表视为论证
如果架构图、对比表、流程图或数据表承担核心关系，就把其中的关系写进正文；不要把图表当装饰。

## 故事、比喻与术语

- 故事：保留 **必要场景 → 冲突/变化 → 关键转折 → 认知落点**。
- 比喻：留在它帮助理解的位置，不单独做“比喻鉴赏”。
- 术语：首次出现时写“术语 + 作者最简解释”；之后用短称呼。
- 原文有“预期 → 反差 → 新认识”时保留最低必要张力，不主动添戏。

## 默认输出

结构可以自然调整，但通常包含：

1. **这篇/这份文档在做什么** — 只做导航，不抢跑。
2. **顺着作者真正的主线走一遍** — 恢复关键推进和认知桥梁。
3. **关键机制、概念或故事为什么重要** — 只讲真正影响理解的部分。
4. **容易被压掉的边界** — 例外、限制、不确定性。
5. **最终提炼** — 陌生读者只看这一节，也能判断文章真正值在哪里。

简单文章允许更短，不为凑结构制造内容。

## 自检

只问五个问题：
- 我有没有提前泄露后文才成立的结论？
- 我有没有删掉让抽象内容变得可理解的故事/机制？
- 我有没有把术语只留名字没留意思？
- 长文里，我有没有把章节摘要拼接当成理解？
- 最终提炼有没有比原文更浅或更夸张？
