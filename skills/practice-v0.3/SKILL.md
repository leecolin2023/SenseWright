# Practice V0.3 — Branch Exploration

## 定位

**Learning 建立对机制的理解；Practice 从已有知识主干或指定研究主题中主动发现、选择并深入值得研究的问题。**

当用户只提供主题而要求 Practice 寻找下一研究问题时，先用最小必要的背景还原其实际目的与关键运行机制，而不是等待用户提供故障或重复完整 Learning。真实提问、应用或反例会暴露未解释的关键决策、隐藏前提和独立枝干。Practice 要把这些问题**找出来、辨别价值、深入推演或验证**，而不是沿主干重复讲解，也不是只选择一个熟悉的异常。

目标：**从一条知识主干，扩展成有重点、能继续研究的问题网络。**

## 工作原则

1. **先确定目的与主干，再找遗漏。** 用已有 Learning、原始材料、指定主题或当前问题，简要还原「现实任务/目标 → 关键机制/决策 → 结果」，检查每个重要转折的依据。特别留意「为何采取这个动作、为何选它而不是别的、输入从何而来、怎样知道完成」。如果必要前提没讲清，这首先是**主干缺口**，不能被降级成可选边枝。简单问题无须画完整流程图。**面对含糊的生产故障反馈时，首先定义可诊断的主问题**：区分报告的现象、已确认事实与原因猜测，按需明确失败表现、影响对象和范围、时间/条件边界及预期结果；优先确定能改变下一步排查方向的第一项核查。已有事实不要重复追问，更不能把“GPU 故障”等未经验证的原因直接当问题。此要求按任务触发，不是所有 Practice 的固定前置表。
2. **从目标和机制主动生成问题空间。** 当输入只有产品、技术或研究主题时，先问它为谁完成什么任务、成功依赖哪些必要行为与条件、哪里必须作选择或面对约束；再从已有真实案例、矛盾、替代方案或有意义的条件变化中推导候选问题。比如模型服务平台的核心任务是让业务稳定调用模型，便可研究“如果原本可用的模型突然无法调用，哪个机制首先可能被破坏”；性能退化、资源隔离与升级兼容同样可能是更好的候选。**案例必须能追溯到真实目标与关键机制，不能从术语随机编造故障**；未有真实事件时明确是代表性假设，而非生产事实。对已有主干也要检查各节点的选择、前提、组合方式、适用边界与结果反馈。区分 **主干缺口 / 有独立研究价值的枝干 / 不影响理解的细节**；不要固定问题数量或机械为术语生成追问。
3. **选值得深入的下一问题，并说清选择理由。** 一个问题至少应该能够补上关键因果解释，或使答案改变理解、判断、行动或结果。结合用户当前任务、核心目标的影响、必要前提、可观察与可区分性、迁移价值判断优先级；不能只按故障严重性或技术复杂度排序。用户要求“为什么研究这个”时，说明它从哪个目标、条件变化或实际矛盾推导出来，以及它为什么比其他候选更值得先研究。明确哪些问题已讨论、哪些尚待研究。
4. **真正深入，而非只列题。** 对选中的问题，用具体情境、回答/尝试、反例或条件变化逼出机制；需要证据时回到源码、数据、原始材料或实际操作。不同枝干可各自形成新的问题链；用户要交互练习就逐轮追问，要求完整研究则适当覆盖多个方向。**区分查证、推演、实际运行和未知**，不捏造验证结果。
   - **生产故障排查驱动（按需）。** 从已经界定的故障现象和实际请求、状态或依赖链出发，提出不同原因假设；选择能区分假设的日志、指标、状态、配置或受控对照，解释为何优先检查、不同观察将把下一步导向何处，以及背后的机制。缺乏现场证据时只给条件式诊断路径，不宣称找到根因或修复成功。**单一故障任务聚焦该故障；全面技术实践仍要发现其他重要的主干缺口与独立枝干**。不把组件清单、固定检查顺序或重启建议当成诊断。
5. **收束与回流。** 说明这轮新增了什么理解，哪些枝干值得单独展开。若发现根本机制未理解，提出新的 Learning 问题；真正发起 L 时仍须独立完成本轮 D/R 前置。P-only 不自动重跑 D/R。若是证据缺失则明确下一步查证，而不是把所有缺口都交给 Learning。

## 交付与边界

以用户目标决定篇幅：需要问题地图就给**简短但有区分度的问题结构和优先级**；需要深度练习就展开实际追问与应对；需要操作就把关键分支落实为可核验的动作。无需固定章节、问题数、工程产物或验收表。

只问“某技术是什么”的定义需求主要由 L 承担；但要求**从指定主题主动发现下一研究问题**属于 P，可据当前目的构建最小必要主干，不必先虚构一次完整 Learning。面试/自测时，**用户没实际回答就不能评价用户掌握程度**；模型示范必须标明是示范。纯定义解释主要由 L 承担；机械题库、单纯代码修复或文件制作不因出现问题就强制运行 P。工程实施可以是实践对象，但不再是 Practice 的默认形态。

交付前只问自己三个问题：

- **漏没漏？** 如果只给主题，是否能追溯“现实目标 → 关键条件或矛盾 → 候选问题 → 选择理由”，而非凭空给题？是否跳过重要的行动选择、因果前提或其他独立方向？
- **深不深？** 每个重点问题是否真的解释或检验了关键差异，而非只有术语和泛泛追问？
- **真不真？** 哪些有依据、哪些只是假设、哪些还没有验证？

**最终原则：先发现值得问的问题，再把重要问题问透。**
