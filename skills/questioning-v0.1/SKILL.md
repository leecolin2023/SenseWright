# Questioning V0.1 — Gap → Probe → Update

## 目标

> **不追求提出更多问题，而是找到当前最值得知道的下一件事。**

Questioning 通过少量、高信息价值的连续追问，把一个模糊问题推进到可验证、可判断、可行动的状态。

基本循环：

`Current Model → Find Critical Uncertainty → Ask → Receive Answer → Update Model → Ask Again`

---

## 一、与其他 Skill 的边界

- 用户主要想知道“原材料说了什么” → Deep Read。
- 用户主要想判断“材料是否成立” → Review。
- 用户主要想建立“自己的知识模型” → Learning。
- 用户主要想知道“接下来应该问什么，并通过追问把问题想清楚” → Questioning。

Questioning 可以承接 Learning 找到的 Knowledge Gap，但不依赖 Learning 的压缩结果作为唯一 Context；有原材料时仍应保留原材料与当前对话状态。

---

## 二、核心原则

### 1. 一次优先推进一个关键问题

默认不要一次输出长问题清单。

先判断：

> 当前哪个未知如果被回答，最可能改变后续理解、判断或行动？

优先询问这个问题。

只有用户明确要求“访谈提纲 / 问题清单”时，才一次生成多个主问题。

### 2. 每个下一问都必须由当前回答触发

收到回答后，更新当前认知状态：

- **Confirmed**：已经被事实或明确回答支持的内容；
- **Assumed**：当前仍只是判断或默认前提；
- **Unknown**：真正缺失的信息；
- **Contradiction**：回答与已有信息之间的冲突；
- **Next Gap**：现在最值得继续减少的不确定性。

然后重新选择下一问。

不要预先机械执行固定 Checklist。

### 3. 优先追真实事实，而不是抽象观点

当回答过于概括时，优先追问：

- 能不能给一个真实例子？
- 当时具体发生了什么？
- 谁做了什么？
- 你本人做了什么？
- 最终结果是什么？
- 你怎么知道结果是好的或坏的？

抽象判断尽量落回事件、行为、证据和结果。

### 4. 先澄清，再挑战

如果概念本身还没有说清楚，不要急着反驳或寻找原因。

先确认：

> 你说的 X 具体指什么？

只有当前命题已经足够清晰，才进一步追：
- 为什么？
- 依据是什么？
- 默认了什么？
- 有没有其他解释？

### 5. 强问题优先于多问题

一个问题的价值来自它减少多少重要不确定性，而不是听起来多深刻。

优先问会改变以下任一事项的问题：
- 问题定义；
- 因果判断；
- 结论可信度；
- 设计选择；
- 风险边界；
- 下一步行动。

### 6. 不要把答案藏进问题

避免诱导：

> “是不是因为权限体系没做好，所以 Agent 才没落地？”

优先：

> “当时阻止 Agent 落地的最主要原因是什么？”

得到“权限”后，再继续问：

> “具体是哪一种权限问题？”

## 三、Question Lens — 按需触发，不按顺序执行

以下 Lens 只是选择下一问时的内部工具，不是固定流程。

### Clarify — 到底在说什么？
- 你真正想解决的问题是什么？
- 这里的 X 具体指什么？
- “好”“有效”“成熟”“失败”的判断标准是什么？

### Reason — 为什么这样判断？
- 你得出这个结论最重要的理由是什么？
- 哪个理由如果不成立，结论会明显变化？

### Evidence — 凭什么相信？
- 这个判断来自数据、案例、个人经验还是别人观点？
- 有没有一个最具体的例子？
- 什么证据会让你改变当前判断？

### Assumption — 默认了什么？
- 要让这个结论成立，哪些条件必须同时成立？
- 哪个前提目前其实还没有验证？

### Alternative — 还有别的解释吗？
- 如果当前解释是错的，还有什么能解释同一现象？
- 为什么当前解释比另一个解释更可信？

### Mechanism — 中间到底怎么发生？
- A 到 B 中间经过了什么过程？
- 哪个环节真正决定结果？

### Boundary — 什么时候不成立？
- 在什么条件下这个结论会失效？
- 有没有反例？

### Missing — 还缺什么？
- 如果今天必须做决定，哪条信息的缺失最危险？
- 有什么重要信息目前完全没有被讨论？

### Action — 下一步应该验证什么？
- 最小可以验证这个判断的动作是什么？
- 应该找谁、看什么数据、跑什么实验？

## 四、访谈式 Probe

当用户或受访者给出一个回答时，不立刻换主题。

优先判断回答缺少的是：

`Situation → Reason → Action → Result → Reflection`

可自然追问：
- 当时具体是什么情况？
- 为什么会发生？
- 你是怎么判断的？
- 你具体做了什么？
- 还有哪些方案被考虑过？
- 为什么没选？
- 最后发生了什么？
- 你怎么知道这个结果成立？
- 如果再来一次，会改变什么？

如果回答出现模糊、矛盾或明显跳跃，优先追这个点，而不是继续预设问题。

---

## 五、三种输出行为

### 连续追问
用户明确要求“和我一起把问题想清楚”时：

> 默认一次只问一个最重要的问题，等待回答后继续。

### 访谈设计
用户要求“帮我准备访谈”时：

> 输出少量主问题，并为每个主问题准备必要 Probe；不要堆几十个问题。

### 下一问建议
用户问“我还应该问什么”时：

> 根据当前最大 Gap 给出少量高价值问题，并说明每个问题解决什么不确定性。

---

## 六、停止条件

Questioning 不是无限追问。

满足以下任一条件，可以阶段性停止：

1. 核心问题已经足够清晰；
2. 关键结论已有足够证据支持；
3. 最大未知已经转化为可验证动作；
4. 后续问题的信息增益明显下降；
5. 下一步必须依赖新的数据、专家或实验，继续语言追问不会再减少不确定性。

结束时简要整理：
- 当前已经确认的认识；
- 仍未解决的核心 Gap；
- 下一步最值得验证的事项。

---

## 七、自检

- 我是在问当前最重要的问题，还是只是问了一个看起来聪明的问题？
- 下一问是否真的来自上一轮回答暴露出的 Gap？
- 我是否过早进入原因分析，而问题本身还没有定义清楚？
- 我有没有把自己的答案塞进诱导性问题？
- 如果这个问题得到答案，它真的会改变后续理解、判断或行动吗？
- 是否已经到了应该停止追问、转入数据/实验/行动验证的时候？

如果最终只是得到一份“10 个值得思考的问题”，Questioning 没有完成任务。
